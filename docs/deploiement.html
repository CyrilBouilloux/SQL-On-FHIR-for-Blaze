Prérequis

Poste de construction

  • bash, make, git, python3, docker, curl, jq, unzip, tar, sha256sum — liste du README, « Démarrage rapide » ; scripts/outils.sh refuse (code 3) si manque curl, unzip, tar, sha256sum, docker ou git.
  • Le dossier est un dépôt git, fichiers suivis : le jar n'archive que ceux-là (construction.md, étape 2/4).
  • Accès réseau à Docker Hub et à Maven Central au moment de make image (construction.md).
  • Aucun JDK pour le jar ni pour l'image. Pour développer le module (tests, conformité) : make outils, puis methode-module.md.

Cluster et poste de déploiement

  • kubectl et helm sur le poste ; versions visées : clés KUBECTL_VERSION, HELM_VERSION et K8S_MINOR de versions.env (K8S_MINOR fixe la version de la politique restricted du namespace).
  • Une StorageClass par défaut qui sert deux volumes ReadWriteOnce, ou une classe nommée par blaze.stockage.classe et blaze.viewdefinitionExport.stockage.classe.
  • Un CNI qui applique les NetworkPolicy (sans lui elles sont acceptées mais sans effet).
  • Des nœuds qui lisent l'image du module : image locale chargée sur les nœuds, ou registre lisible par eux avec image.blaze.registry et image.blaze.digest (configuration.md).
  • Mémoire disponible pour le pod Blaze au moins égale à sa limite (ressources.blaze de values.yaml).

Pour essayer sans cluster : prérequis et lancement de la démonstration docker compose dans demo/README.md, « Prérequis » (outil de poste, hors livraison).

Installer, dans l'ordre

build/construire-jar.sh          # jar du module
scripts/outils.sh jar            # jar de l'image publiée, pour la comparaison de make check
make check                       # SUCCES attendu
make image                       # image du module
kubernetes/chart/deriver.sh      # Chart.yaml et values-versions.yaml dérivés de versions.env
helm upgrade --install blaze kubernetes/chart -n blaze -f kubernetes/chart/values-versions.yaml \
  --set image.blaze.repository="$IMAGE" --set image.blaze.tag="$TAG"

La création du namespace avec ses métadonnées d'adoption, le calcul de TAG et le cas du registre sont dans README, « Déployer » ; chaque étape de construction dans construction.md.

Joindre l'API depuis le poste (exposition.type: ClusterIP, défaut) :

kubectl -n blaze port-forward svc/nginx 8088:8090
export FHIR=http://localhost:8088/fhir

Commande non mesurée dans ce dépôt ; 8088 est le port de blaze.baseUrl par défaut. Avec exposition.type: NodePort, l'API est sur le port exposition.nodePort de chaque nœud. L'API est ouverte, sans authentification : usage local uniquement (README, avertissement).
