Toute extension de Blaze par le module (overlay de `blaze.edn`, `ig/init-key`, `defmethod`,
`extend-protocol`, `extend` par fusion, appel d'une fonction interne) figure ici **avant** sa
livraison, une ligne par point touché. Les extensions sont globales à la JVM : elles touchent
aussi l'indexation et toute la pile (ADR 0003, conséquences).

Sources au tag **v1.11.0** (`git -C amont/blaze describe --tags --exact-match` → `v1.11.0`,
2026-10-09) ; chemins relatifs à `amont/blaze/`. `fp` = `modules/fhir-path/src/blaze/fhir_path.clj`.
Une montée de version (ADR 0003, point 7) **revérifie chaque ligne** : fichier, lignes, et
l'état mesuré des implémentations.

**Mesures** du 2026-10-09 sur le jar publié (`.work/blaze-standalone.jar`), depuis
`modules/sql-on-fhir` : `eval "$(../../scripts/outils.sh env)"` puis
`clojure -Sdeps '{:deps {blaze/publie {:local/root "../../.work/blaze-standalone.jar"}}}' -M -e '<forme>'`.

## Fiche de panne — IB-12, sortie brute de `$viewdefinition-run`

**Ce qui peut casser.** `$viewdefinition-run` renvoie ses lignes en contournant l'encodeur
FHIR de Blaze : le module met les lignes de côté dans la réponse, laisse le corps vide, et
les remet en place après le passage de Blaze. Cela marche parce que Blaze, aujourd'hui,
laisse passer ce qu'il ne connaît pas et n'encode pas un corps vide. Si une version de
Blaze change l'un de ces deux comportements, l'opération répond encore, mais mal.

**Quand.** Seulement après une montée de version de Blaze (`BLAZE_VERSION` et
`BLAZE_IMAGE_DIGEST` de `versions.env`) : l'image est épinglée par empreinte, rien ne
change sans ce geste. Le test du module le détecte **avant** la livraison.

**Symptôme vu du client.** Les autres routes vont bien (`/fhir/metadata` 200, recherches
normales). Seule `POST /fhir/$viewdefinition-run`, sur une vue qui devrait rendre des
lignes, répond `200` mais :
- corps vide (0 octet) — Blaze a perdu les lignes mises de côté ; ou
- corps `null`, ou `Content-Type: application/fhir+json` au lieu de
  `application/x-ndjson`, `application/json` ou `text/csv` — Blaze a encodé le corps vide.

**Diagnostic, du moins coûteux au plus coûteux.**
1. Sur le poste, contre le jar de la version visée :
   `make -C modules/sql-on-fhir test-focus FOCUS=blaze.addon.sql-on-fhir.operation.sortie-amont-test`
   — attendu `0 failures.` ; le message d'échec nomme le comportement perdu (clé conservée,
   ou corps `nil` non encodé). Obtenu (T-032) : `2 tests, 2 assertions, 0 failures.`
2. Sur un déploiement, une vue minimale sur `Patient` :
   ```
   curl -s -o /dev/null -w '%{http_code} %{content_type} %{size_download}\n' -X POST \
     -H 'Content-Type: application/fhir+json' \
     --data '{"resourceType":"Parameters","parameter":[{"name":"viewResource","resource":{"resourceType":"ViewDefinition","status":"active","resource":"Patient","select":[{"column":[{"name":"id","path":"id"}]}]}}]}' \
     'http://localhost:8088/fhir/$viewdefinition-run?_format=ndjson'
   ```
   Attendu, opération livrée et au moins un `Patient` chargé : `200 application/x-ndjson <taille > 0>`.
   Panne : `200` avec taille `0`, ou `Content-Type` `application/fhir+json`. Obtenu le
   2026-10-12 sur un déploiement (image du module `1.11.0-e1e6e58c846c`, jeu de référence, 114 `Patient`) :
   `200 application/x-ndjson 2964` (relevé de départ du 2026-10-10, image nue : `404 … 85`).
   Rejoué par le cas d'intégration IT-022 (même commande, base d'URL `HAPI_BASE_URL`)
   — attendu `SUCCES`, code 0 ; en panne `ECHEC` (code 8), message citant IB-12 (T-040).
   La taille suit le nombre de `Patient` : joué avec la suite entière des cas, IT-022 voit
   aussi les 5 `Patient` `fhir-platform-test-*` d'IT-016 et IT-021, supprimés en fin de suite →
   `200 application/x-ndjson 3170` (+206 octets, 119 lignes), mesuré par `architect` le 2026-10-12.
3. Lire `output.clj` au nouveau tag (`scripts/outils.sh amont`) : `encode-response-json` et
   `handle-response` ; comparer avec la source citée en IB-12.

**Remède.**
- **Tout de suite** (déploiement touché) : couper l'opération, `DISABLE_VIEWDEFINITION_RUN=true`
  (valeur du chart `blaze.viewdefinitionRun.actif=false`) ; cas IT-020 `état true : 404`, 2026-10-12) — elle rend alors 404, le reste du serveur est
  intact ; ou revenir à la version précédente de Blaze dans `versions.env`.
- **Durablement** : refaire la mesure de T-028 Q2 sur la nouvelle version et adapter le
  composant d'enrobage au nouveau comportement, ligne IB-12 et test mis à jour dans la même
  livraison. Si aucune voie ne tient par les points d'extension : arrêt et escalade humaine
  (ADR 0003, point 5) — pas de contournement.
